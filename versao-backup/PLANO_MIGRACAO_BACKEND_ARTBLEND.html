SQL pronto pra criar tudo isso (é só colar no Supabase)

-- Clientes (compartilhado por todas as ferramentas)
create table clientes (
  id uuid primary key default gen_random_uuid(),
  owner_id uuid references auth.users(id) not null,
  nome text not null,
  created_at timestamptz default now()
);

-- Uma tabela genérica por ferramenta (cada uma guarda o "estado" daquele cliente em JSON,
-- do mesmo jeito que hoje fica salvo no localStorage — migração direta, sem redesenhar telas)
create table dados_ferramenta (
  id uuid primary key default gen_random_uuid(),
  cliente_id uuid references clientes(id) on delete cascade,
  ferramenta text not null, -- 'kit_operacional' | 'frameworks' | 'financeira' | 'compliance' | 'nr1' | 'cep' | 'cardapio'
  conteudo jsonb not null default '{}',
  updated_at timestamptz default now(),
  unique(cliente_id, ferramenta)
);

-- CRM (carteira do consultor, não é por cliente único)
create table crm_agenda (
  id uuid primary key default gen_random_uuid(),
  owner_id uuid references auth.users(id) not null,
  cliente_id uuid references clientes(id),
  data date, tipo text, nota text, status text default 'pendente',
  created_at timestamptz default now()
);

-- Segurança: cada consultor só vê os próprios clientes
alter table clientes enable row level security;
create policy "cada um vê só o seu" on clientes
  for all using (owner_id = auth.uid());

alter table dados_ferramenta enable row level security;
create policy "cada um vê só os dados dos próprios clientes" on dados_ferramenta
  for all using (
    exists (select 1 from clientes c where c.id = dados_ferramenta.cliente_id and c.owner_id = auth.uid())
  );

alter table crm_agenda enable row level security;
create policy "cada um vê só a própria agenda" on crm_agenda
  for all using (owner_id = auth.uid());

Como a migração acontece na prática, ferramenta por ferramenta

1
Trocar só a "gaveta". Cada ferramenta já tem as funções load() e save() centralizadas (é assim que foi construída desde o início, de propósito). Eu troco só o miolo dessas duas funções pra chamar o Supabase em vez do localStorage — o resto do código (telas, cálculos, botões) não muda nada.
2
Login único. Adiciono uma tela de entrada simples (e-mail/senha) na frente do Hub — depois de logado, tudo funciona igual a hoje.
3
Testar com seus dados reais — migro o que já está salvo no seu navegador hoje pro banco novo, pra não perder nada do que você já cadastrou.
4
PWA instalável — deixo o Hub instalável no celular direto do navegador, sem loja, pra você validar no dia a dia.
5
Play Store (só depois de validado) — embalar e publicar, com a conta de desenvolvedor Google (US$ 25 único).

Por que essa ordem

O banco de dados é o "esqueleto" — só se faz uma vez e tudo o resto se apoia nele. Deixar a Play Store por último evita ter que redesenhar telas se algo mudar no meio do caminho, e o PWA permite validar com uso real (inclusive com clientes) sem gastar nada nem esperar aprovação de loja.
