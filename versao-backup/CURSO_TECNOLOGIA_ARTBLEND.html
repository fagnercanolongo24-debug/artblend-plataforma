Como funciona o app ArtBlend

Você não precisa saber programar pra usar as ferramentas — mas entender o básico ajuda a pedir mudanças certas, saber o que é possível hoje e o que só dá pra fazer quando virar um app "de verdade".

1. O que é, de fato, cada arquivo

Cada ferramenta (Kit Operacional, NR-1, CEP, Cardápio, CRM...) é um único arquivo HTML. HTML é a linguagem que o navegador entende pra desenhar páginas. Dentro desse mesmo arquivo tem três partes:

ParteO que faz
HTMLO esqueleto — os textos, botões, tabelas, campos.
CSSA aparência — cores, espaçamento, a identidade visual (o turquesa/azul-marinho).
JavaScript (JS)O comportamento — o que acontece quando você clica, digita, calcula um CMV, troca de cliente.

Por isso dá pra abrir qualquer uma dessas ferramentas com duplo clique — não precisa instalar nada, não depende de internet.

2. Onde ficam os dados que você digita

Tudo que você digita (fichas técnicas, clientes, diagnósticos) é salvo no localStorage — uma "gaveta" que o próprio navegador (Chrome, Edge) guarda no seu computador, associada àquele arquivo específico.

🐱 O detalhe importante

Essa gaveta é por navegador e por arquivo. Se você abrir o mesmo arquivo em outro computador, ou apagar os dados do navegador, os dados não vão junto — porque não existe um servidor central guardando isso, é só o seu navegador. É por isso que existe o botão "Exportar dados" em quase todas as ferramentas: ele salva um arquivo .json que funciona como um backup que você pode guardar ou levar pra outro computador.

3. O "seletor de cliente"

Nas ferramentas mais novas (NR-1, CEP, Cardápio, Compliance, Kit Operacional, Frameworks, Financeira) tem uma caixinha no topo pra trocar de cliente. Por trás disso, cada cliente tem sua própria "gaveta" dentro do localStorage — trocar de cliente só troca qual gaveta está sendo lida e escrita. Assim os dados de um restaurante nunca se misturam com os de outro.

4. O que é fácil de pedir, o que é difícil

Fácil de mudar (rápido)Difícil de mudar (exige mais tempo/planejamento)
Textos, cores, ordem de camposFazer os dados aparecerem em outro computador/celular automaticamente
Adicionar uma pergunta, uma coluna, um campoVários consultores acessando o mesmo cliente ao mesmo tempo
Novos cálculos simples (uma fórmula nova)Publicar como app de verdade na Play Store
Unir duas ferramentas numa sóLogin/senha por usuário, permissões diferentes

A coluna da direita é justamente o que exige migrar de "arquivo HTML sozinho" para um app com servidor/banco de dados de verdade — que já está anotado como próxima etapa grande do projeto (mas só depois de todo o conteúdo estar unificado, pra não ter que redesenhar tudo de novo).

5. Glossário rápido (os termos que aparecem nas conversas)

  • Front-end: a parte visual, o que você vê e clica (é basicamente o que essas ferramentas HTML já são).
  • Back-end: o "motor" que roda num servidor, guarda os dados de todo mundo num banco de dados central, permite login. É o que ainda falta pra virar um app publicável.
  • Banco de dados: onde os dados ficariam guardados de verdade (em vez do localStorage do navegador).
  • App nativo / Play Store: versão instalável no celular — normalmente é uma "casca" em volta do front-end + back-end.
  • Sandbox / ambiente: um computador temporário e isolado que eu uso pra rodar comandos técnicos (às vezes ele cai — foi o que aconteceu nesta sessão, por isso não consegui abrir os arquivos .docx direto).
  • JSON: o formato de arquivo usado nos backups ("Exportar dados") — é só um jeito organizado de guardar texto.
Resumo em 1 frase

Hoje você tem várias "casas" (arquivos) muito bem decoradas e organizadas, cada uma guardando suas próprias coisas na gaveta do navegador; o próximo salto é construir um "prédio" (servidor + banco de dados) que conecta todas as casas e deixa qualquer pessoa, de qualquer lugar, acessar os mesmos dados.
